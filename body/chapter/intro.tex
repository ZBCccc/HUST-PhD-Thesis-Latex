\chapter{绪论}\label{chap:intro}
\section{研究背景与意义}
云计算作为当前主要的数据外包基础设施，为政府机构、企事业单位与个人用户提供了弹性存储与计算服务\cite{armbrust2010view}。然而，数据外包在提升资源利用率的同时，也使电子医疗记录、金融交易流水、企业核心知识资产以及政府档案等敏感信息暴露于泄露、越权访问与滥用风险之下；近年来多起数据泄露事件以及 GDPR\cite{GDPR2018EU}、《数据安全法》\cite{PRC2021DataSecurityLaw} 等监管要求进一步表明，云环境中的数据机密性与完整性保护已成为不可回避的现实问题\cite{ren2012security,CNNBiz2019CapitalOneBreach,BusinessInsider2021FacebookBreach}。

在典型云存储架构中，云服务器常被建模为"半诚实"（semi-honest）实体\cite{goldreich2004foundations}。该安全模型假设云服务器会按协议规范执行存储与检索流程，但可能利用其对基础设施的控制能力，通过观察数据副本、查询频率与访问模式等信息推断用户隐私内容\cite{yang2006privacy}。除半诚实行为外，云环境还面临外部持续性攻击与内部越权操作等风险，使得机密性保护与服务可信性保障同时成为系统设计的核心目标\cite{cloud2011nist}。

加密技术是实现云端数据机密性保护的基本手段。数据在上传前加密可降低静态数据泄露风险，但传统加密方案将明文语义映射为随机化密文，导致云服务器无法在密文状态下直接完成关键词检索、过滤与统计等操作。若用户需检索包含特定关键词的文档，则需下载全部相关密文并在本地解密后检索，其通信与计算开销随密文总量线性增长。

为在机密性与检索可用性之间取得平衡，可搜索加密（Searchable Encryption, SE）通过构造加密索引与检索陷门（trapdoor），使云服务器能够在不获知明文内容的情况下完成匹配检索\cite{song2000practical}。根据密钥体系的不同，可搜索加密分为公钥可搜索加密（PEKS）\cite{boneh2004public} 与对称可搜索加密（SSE）\cite{curtmola2006searchable}。其中，SSE 因计算效率高且适用于数据拥有者主导的外包存储场景，成为云存储场景下的研究重点。

面向真实云服务部署场景时，现有 SSE 方案仍存在两类问题。
其一，多用户协作访问需求与授权机制复杂性之间的矛盾。在企业文档管理、医疗信息共享、多部门协同办公等典型应用场景中，数据拥有者需要将加密数据授权给多个用户进行检索与访问\cite{fu2015achieving}。多用户场景引入了密钥分发、用户撤销、权限动态变更与跨用户串通防护等新挑战，且这些机制需与 SSE 的索引结构、陷门生成过程协同设计，否则将引入额外泄露或显著增加系统开销。
其二，多关键词组合查询的表达能力需求与隐私泄露控制之间的张力。现实检索场景中的查询具有多关键词与布尔组合特征，单关键词检索难以满足精细化的信息获取需求\cite{sun2013privacy,cao2013privacy}。多关键词查询需要在表达能力与泄露控制之间寻求平衡，尤其是在合取或析取查询中，结果集合之间的关系可能被云服务器观察，从而放大查询语义泄露风险。

本文不直接解决上述两类挑战本身，而是以 Nomos 为代表的已有多用户多关键词 SSE 方案为基础，在继承其多用户授权与查询隐私设计的前提下，专注于引入可验证性机制。在上述两类挑战之外，现有多数 SSE 研究主要在泄露受限的隐私模型下讨论机密性保证\cite{bosch2014survey}，而对云服务器可能偏离协议执行、返回不完整或错误搜索结果的问题研究不足\cite{chai2012vsse}。该类协议偏离行为虽未必直接破坏密文机密性，却会影响检索服务的正确性与可用性。具体而言，可验证性涉及三类独立的安全目标：正确性（correctness），即返回文档确实匹配查询条件且未被篡改；完整性（completeness），即所有匹配文档均被返回而未被删减；健全性（soundness），即云服务器无法伪造通过验证的错误结果。在医疗诊断、审计追溯、应急指挥等依赖检索结果完整性的业务场景中，上述任一属性的缺失均可能导致不可接受的后果。因此，如何使授权用户能够有效检测云服务器返回结果的正确性、完整性与健全性，即搜索结果的可验证性问题，是本文研究的核心问题。

多用户多关键词 SSE 场景下的可验证性问题需要在理论与应用两个层面展开研究。在理论层面，可验证可搜索加密（Verifiable Searchable Encryption, VSE）需要同时协调可搜索加密、访问控制与可验证计算等密码学原语。在多用户多关键词设置下，验证机制需要同时处理授权资格检验的正确性与搜索结果集合的完整性，这对认证数据结构的构造与更新维护策略提出了新的理论挑战。该复合场景下如何以较低的额外开销引入可验证机制是核心研究问题。在应用层面，可验证性保障使用户无需信任云服务器即可确认检索结果的正确性与完整性。对于医疗健康、金融审计、政务档案等对数据完整性要求严格的应用领域，可验证 SSE 可降低对云服务器诚实性的依赖。



\section{国内外研究现状}
可搜索加密的研究已从静态单关键词单用户模型演进至动态多关键词多用户模型。在理论层面，安全性定义从早期的非自适应安全逐步发展至自适应安全、前向安全性与后向安全性等更强的安全属性；在功能层面，从单关键词精确匹配扩展至多关键词布尔查询、排序搜索与模糊搜索；在应用层面，从单用户场景扩展至多用户协作场景，引入了访问控制、用户撤销与权限管理等机制。在上述演进过程中，可验证性作为保障云服务器诚实执行协议的关键属性，逐渐成为 SSE 研究的重要方向。本节从对称可搜索加密基础理论、多用户扩展与可验证性增强三个维度梳理相关研究进展。

\subsection{对称可搜索加密基础理论与安全性演进}
\textbf{奠基性工作与形式化安全模型}。Song 等人\cite{song2000practical}于 2000 年首次提出具有实用意义的对称可搜索加密方案，通过在加密文档中嵌入可搜索结构，证明了在密文上执行关键词搜索的可行性。该工作开创了 SSE 研究领域，但其方案的搜索复杂度与文档总长度线性相关，且缺乏形式化的安全性定义。随后，Goh \cite{goh2003secure} 引入安全索引（secure index）概念，利用布隆过滤器为每个文档构建关键词索引，将搜索复杂度降至与文档数量线性相关，并给出了基于模拟的安全性定义。在公钥体系下，Boneh 等人\cite{boneh2004public}提出 PEKS 概念，支持第三方在不持有私钥的情况下生成检索陷门，但计算开销显著高于对称体系。

Curtmola 等人\cite{curtmola2006searchable} 的工作是 SSE 形式化安全理论的里程碑。该文给出了非自适应安全（non-adaptive security）与自适应安全（adaptive security）两种安全性定义，前者假设敌手在获取加密索引前提交所有查询，后者允许敌手根据已观察到的信息自适应地选择后续查询。基于该形式化框架，作者构造了可证明安全的 SSE 方案，其搜索复杂度仅与匹配文档数量相关（即次线性搜索），奠定了后续 SSE 安全性分析的理论基础。

\textbf{动态 SSE 与前向/后向安全性}。早期 SSE 方案主要针对静态数据集设计。动态数据需求推动了支持文档添加与删除的动态 SSE（Dynamic SSE）研究。动态场景引入了更新模式（update pattern）等额外泄露面，使隐私保护面临新的挑战。若敌手能够关联更新操作与后续查询结果，则可能推断新增文档的关键词信息或已删除文档的历史存在性。为应对上述泄露风险，研究者提出了前向安全性（forward security / forward privacy）与后向安全性（backward security / backward privacy）等安全属性。前向安全性要求新增文档的更新操作不泄露其与历史查询的关联性，后向安全性要求删除操作后，后续查询结果不泄露已删除文档的历史信息。Bost\cite{bost2016ovarphiovarsigma}提出的 \textit{Sophos}（$\Sigma o\phi o\varsigma$）方案是前向安全 SSE 的代表性工作，通过陷门置换与状态演化机制实现高效的前向安全性保护。在后向安全性方向，Bost 等人\cite{bost2017forwardbackward}首次给出了同时支持前向安全性与后向安全性的动态 SSE 构造，并基于约束伪随机函数（Constrained PRF）与可穿透加密（Puncturable Encryption）给出对应安全设计。随后，Sun 等人\cite{sun2018practical}提出 Janus++ 方案，使用对称可穿透加密（Symmetric Puncturable Encryption）替代公钥原语，并在其设定下报告了更低的计算开销。同年，Chamani 等人\cite{chamani2018new}基于代数构造提出了新的前后向安全性方案，为动态 SSE 提供了不同的技术路径。在安全性增强方面，Zuo 等人\cite{zuo2019dynamic}提出了更强的后向安全性（Type-I$^-$，即 Type-I minus）定义，并设计了仅需一次往返即可实现的强安全方案。此外，Demertzis 等人\cite{demertzis2020dynamic}提出了亚线性客户端存储的后向安全性方案。

\subsection{多用户可搜索加密研究现状}
\textbf{共享密钥扩展与早期授权机制}。多用户可搜索加密（Multi-user SSE）场景对应一个数据拥有者（Data Owner）对多个数据用户（Data User）授权搜索与访问的体系结构。早期研究采用共享检索密钥策略，使所有授权用户持有相同的主检索密钥以生成检索陷门。该方式实现简单，但在可管理性与安全性方面存在明显局限：单个用户密钥泄露即可导致全系统密钥暴露，用户撤销与权限变更需进行高成本的密钥重分发与索引重加密操作。为降低数据拥有者的在线参与负担并提升授权粒度控制能力，Fu 等人\cite{fu2015achieving}研究了多关键词排序搜索场景下的多用户授权问题，引入授权令牌机制使数据拥有者能够以较低交互成本授权用户发起受限查询。多客户端 SSE（Multi-client SSE）路线进一步探索了授权能力限制与辅助授权信息的设计。Popa 等人\cite{popa2013multi}提出多密钥可搜索加密方案，支持不同用户持有独立密钥进行搜索。Sun 等人\cite{sun2016protecting}研究了数据拥有者强制搜索授权机制，实现了细粒度的搜索权限控制。

\textbf{属性基加密与代理重加密路线}。在更强授权语义需求下，属性基加密（Attribute-Based Encryption, ABE）与关键词搜索相结合的技术路线，通过将访问策略嵌入密文或密钥中，实现细粒度的访问控制。Zheng 等人\cite{zheng2014vabks}提出的 VABKS 方案首次将属性基加密与可搜索加密结合，支持可验证的外包加密数据搜索。该路线支持灵活的策略表达，但其计算代价通常高于对称体系。另有研究探索利用代理重加密（Proxy Re-Encryption）原语。Shao 等人\cite{shao2010proxy}首次提出了支持关键词搜索的代理重加密方案，实现了搜索权限的安全委托。Wang 等人\cite{wang2012further}对该方案进行了改进，提出了支持合取关键词搜索的构造。

\textbf{现代多用户动态 SSE 与隐私增强}。近期研究重点转向多用户场景下动态更新、前后向安全性与抗串通攻击的协同实现。Liu 等人\cite{liu2020multi}在通用可组合（UC）安全框架下提出了支持动态更新的可验证多用户 SSE 方案（MVSSE）。Wu 等人\cite{wu2023enabling}进一步引入了可追踪性（Traceability）与撤销机制，利用混合云架构抵御文件注入攻击。Chamani 等人\cite{chamani2022multiuser}的工作（$\mu$SE）是多用户动态 SSE 形式化理论的突破，首次定义了多用户设定下的前后向安全性，并设计了首个能抵御恶意用户与服务器串通的方案，其验证机制基于区块链摘要发布。Sultan 等人\cite{sultan2023multiclient}针对 IoT 场景设计了支持前后向安全性的多客户端方案，引入了高效的用户撤销机制。Le 等人\cite{le2023muses}提出的 MUSES 方案实现了次线性搜索效率，并有效抵御了关键词猜测攻击。Zhao 等人\cite{zhao2025efficient}提出的 FB-VDSSE 方案进一步统一了前后向安全性与可验证性，通过优化验证结构降低了证明生成开销。Bag 等人\cite{bag2024nomos}提出的 Nomos 方案引入可信授权管理方与 OPRF 协议，在保护查询隐私的同时实现了多用户动态 SSE 的高效构建。最新的研究（如 2024 年 Fast-MUSE \cite{bulbul2024fast}）则探索在维持 Type-II 后向安全性的前提下，利用对称原语进一步降低多用户场景的计算成本。这些进展表明，在同时保障前后向安全性、可验证性与抗串通性的条件下提升系统性能，是当前多用户 SSE 研究的核心趋势。

\subsection{可验证可搜索加密技术研究现状}
在标准 SSE 安全模型中，恶意云服务器可能偏离协议规范：删减匹配文档以降低自身计算开销，插入无关文档，或伪造搜索结果。可验证可搜索加密（Verifiable Searchable Encryption, VSE）旨在使用户能够检测上述偏离行为，具体包括验证搜索结果的完整性（所有匹配文档均被返回）与正确性（返回文档确实匹配查询条件且未被篡改），且验证过程不向云服务器暴露额外隐私信息。

Baek 等人\cite{baek2008public}在重新审视 PEKS 安全性定义的工作中，针对公钥可搜索加密场景提出了更强的安全模型并讨论了结果一致性验证问题，为后续 VSE 研究中的验证模型设计提供了早期参考。Chai 与 Gong\cite{chai2012vsse}针对半诚实云服务器模型，提出了可验证对称可搜索加密（Verifiable SSE）方案，通过为搜索结果附加认证信息，使用户能够检测结果的完整性。Kurosawa 与 Ohtaki\cite{kurosawa2013update}首次形式化定义了动态 SSE 中的可验证更新问题，提出了支持文档增删操作的可验证机制。Cheng 等人\cite{cheng2015verifiable}利用不可区分混淆（iO）技术构造了可验证 SSE 方案，并给出针对恶意云服务器的结果验证机制。Sun 等人\cite{sun2015catch}针对大规模动态加密数据，提出了高效的合取关键词可验证搜索方案，支持top-$k$排序结果的完整性验证。Ogata 与 Kurosawa\cite{ogata2017efficient}进一步提出了无需预定义关键词字典的可验证 SSE 方案，增强了方案的实用性。在多用户场景下，Liu 等人\cite{liu2020multi}提出了支持多用户的可验证对称可搜索加密方案，实现了用户访问控制与结果验证的结合。Zhang 等人\cite{zhang2019efficient}研究了前向安全与可验证性的联合实现，在动态更新场景下同时保证隐私保护与结果可验证。研究者还探索了基于区块链\cite{chen2020blockchain,li2021blockchain}的新型可验证机制，利用区块链的不可篡改特性实现搜索结果的公开可验证性与去中心化审计。

从泄露配置（leakage profile）角度审视上述 VSE 方案，已有工作在泄露控制维度上存在显著差异。Kurosawa 等人\cite{kurosawa2013update}、Chai 与 Gong\cite{chai2012vsse}主要关注搜索模式（search pattern）与访问模式（access pattern）的泄露，验证机制的引入未改变底层 SSE 的泄露配置。Zhang 等人\cite{zhang2019efficient}需额外考虑更新模式（update pattern）泄露，并在前向安全性约束下设计验证结构。Liu 等人\cite{liu2020multi}还涉及用户身份与授权关系的泄露面。然而，已有 VSE 研究较少系统讨论验证机制本身引入的额外泄露（如验证证明的长度是否泄露结果集规模、验证交互是否暴露查询结构信息）。本文方案在 Nomos 的泄露配置基础上引入可验证机制，预期额外泄露限于验证证明的长度信息，不扩大服务器侧的搜索语义泄露边界。

\section{研究目标与内容}
多用户多关键词对称可搜索加密场景下，核心研究问题是在泄露受限隐私保护模型下，如何在保持原有检索效率与动态更新能力的前提下引入轻量可验证机制。围绕这一问题，本文的研究目标是使授权用户能够验证云服务器在搜索流程中的关键步骤是否按协议执行，并检测搜索结果的完整性与正确性，从而提升密文检索服务的可信性。

围绕上述目标，多用户多关键词 SSE 的系统模型与威胁模型需明确云服务器偏离协议时的攻击面与验证需求。可验证性需求被拆分为两个正交维度：位值真实性与地址归属正确性。前者关注服务器在资格检验中是否如实报告概率数据结构的判定位值，后者关注服务器在交叉测试中使用的物理地址是否属于合法认证集合。两个维度的组合在显式认证关系与主项候选枚举完整性双重前提下，为搜索结果的正确性与完整性提供可验证性保障。相应地，本文并非将标准 VSE 的正确性、完整性与健全性三类目标机械地一一映射为单个性质，而是面向 Nomos 的具体协议流程构造验证属性集合：第二章围绕位值真实性给出正确性、绑定健全性、版本一致性与条件完整性四项形式化定义，第三章围绕地址归属正确性给出地址绑定健全性定义，并分析两类机制在显式认证关系上的受限组合接口。

针对位值真实性维度，在现有基于概率数据结构的设计上引入密码学承诺层，使用户能够验证服务器报告的判定位值未被伪造。针对地址归属正确性维度，利用更新阶段的可信计算，对完整地址集合建立根认证并在搜索阶段执行选择性开封，在不显著增加索引规模的条件下支持地址正确性验证。为便于后文表述，本文将由第二章和第三章两类机制共同构成的可验证 Nomos 扩展方案简称为 VQNomos（Verifiable Qualification Nomos），以区别于基础 Nomos 方案。最后，所提机制的安全性与可验证性通过形式化分析证明，验证机制引入后的开销与性能影响通过实验评估量化。

本文的主要创新点如下：
\begin{enumerate}
  \item 提出基于 Merkle Hash Tree 的可验证资格检验机制 $\Pi_{\mathsf{VQ}}$，为多用户 SSE 中基于概率数据结构的资格检验提供可验证的密码学证据，使客户端能够检测服务器对判定位值的伪造，并形式化证明其正确性、绑定健全性、版本一致性与条件完整性。
  \item 提出基于 Merkle-open 的地址绑定验证机制，通过对完整交叉标签集合建立根认证并对采样位置执行选择性开封，实现地址绑定健全性，并给出与 $\Pi_{\mathsf{VQ}}$ 在显式认证关系上的受限组合接口分析。
\end{enumerate}

此外，本文对两类机制进行渐近复杂度推导与原型实验评估，从索引构建、搜索证明生成、客户端验证与通信四个维度量化验证机制引入后的额外开销。

图\ref{fig:intro-tech-roadmap}展示了从 Nomos 方案出发依次引入两类可验证机制的技术路线。VQNomos 方案层继承 Nomos 的多用户多关键词动态 SSE 架构，在保持其检索效率与动态更新能力的前提下，机制层-I 引入基于 Merkle Hash Tree 的可验证资格检验（第2章），机制层-II 引入基于 Merkle-open 的地址绑定验证（第3章），评估层对安全性、可验证性与性能开销进行综合分析（第4章）。两类可验证机制的核心设计如下：

第一，基于 Merkle Hash Tree 的可验证资格检验机制。现有多用户 SSE 方案通常采用布隆过滤器等概率数据结构实现授权用户的资格检验，该类结构存在固有的假阳性率，且无法向用户提供检验结果的密码学验证证据。本机制通过 Merkle Hash Tree 对概率数据结构的位数组建立承诺层，为资格检验结果生成可验证的成员性证明路径。该机制的核心改进在于：（1）为概率数据结构的判定位值提供密码学真实性保证，使客户端能够检测服务器对判定位的伪造（在正确性条件下，概率结构固有的假阳性风险不被放大）；（2）使授权用户能够检测云服务器的选择性作弊行为，从结构层面增强多用户场景下的系统可信性。该机制在授权信息更新时需要重构部分树结构，但在用户数量与查询频率的典型比例下，更新开销处于可接受范围。

第二，基于 Merkle-open 的地址绑定验证机制。现有可验证 SSE 方案通常为验证信息构建独立的认证索引结构，导致存储开销与维护复杂度显著上升。Merkle-open 机制在数据更新阶段对完整地址集合建立根认证，并在搜索阶段仅对令牌采样到的 $k$ 个地址执行选择性开封。该机制的核心改进在于：（1）无需在搜索阶段恢复完整的 $\ell$ 维地址集合，验证流程与 Nomos 的 $k$ 位置采样语法保持一致；（2）对显式返回根认证对象的关系，根认证与路径开封保证云服务器无法把证明切换到认证集合之外；（3）验证过程在用户端完成，验证复杂度与返回结果规模线性相关，不依赖云服务器的诚实性。

\section{论文结构}
全文由五章构成，结构如下。

第一章为绪论，阐述研究背景与意义，梳理国内外研究现状并归纳关键挑战，概述本文研究目标、研究内容与创新点，并给出全文结构安排。

第二章提出基于 Merkle Hash Tree 的可验证资格检验机制。该章首先建立系统模型与威胁模型，介绍多用户多关键词 SSE 的协议交互流程与安全性定义；随后梳理 Nomos 协议的结构，分析 RBF 资格检验机制的可验证性缺口，明确攻击面与可验证性目标；进而给出基于 MHT 承诺层的可验证资格检验机制 $\Pi_{\mathsf{VQ}}$ 的结构设计与算法流程；最后对正确性、绑定健全性、版本一致性与条件完整性进行形式化安全性分析。

第三章提出基于 Merkle-open 的地址绑定验证机制。该章针对第二章机制在 OPRF 盲化架构下遗留的地址替换攻击面，形式化定义地址绑定健全性安全目标；给出对完整交叉标签集合建立 Merkle 根认证并对采样位置执行选择性开封的构造方案，描述扩展更新、搜索证明与验证算法流程；对地址绑定健全性进行形式化证明，并说明其与第二章机制在显式认证关系上的受限组合接口。

第四章对两类可验证机制进行复杂度分析与性能评估。该章建立统一的分析框架与参数体系，从索引构建与更新、搜索与证明生成、客户端验证以及通信四个维度推导各机制引入的渐近额外开销，并与 Nomos 方案进行对比；随后通过原型实现实验对理论分析进行量化验证，考察关键参数对性能的实际影响。

第五章给出总结与展望。该章总结全文工作，讨论研究局限，并就前向/后向安全性与可验证性的联合实现、更丰富查询语义、去中心化可验证搜索及大规模性能优化等方向提出未来研究展望。
