# Merkle-open 改造方案审查报告（Review V2）

## 1. 审稿三大问题的回应评估

### 问题 2.1（归约自相矛盾：持有 $K_T$ 却声称不持有 $K_E$）

**状态：✅ 完全解决**

改造方案彻底删除 $K_E$ 和 AE 归约，换成签名 EUF-CMA + Merkle 抗碰撞。原来的矛盾不是"写错了一句话"，而是整条归约路线在多密钥 AE 场景下无法自洽。新方案的证明（命题 5 的 $G_0 \to G_1 \to G_2$ 游戏跳跃）每一步归约目标清晰，不存在"持有主密钥却假装不持有派生密钥"的逻辑问题。

### 问题 2.2（Verify' 算法不可执行，缺少 $K_E$ 派生步骤）

**状态：✅ 完全解决**

改造方案把客户端验证从"对称解密"改成"签名验证 + Merkle 路径验证"。算法 3（`commitment.tex:199-239`）的输入参数完整：$\mathsf{pk}_G$ 是公钥、$\mathsf{rt}$ 和 $\sigma$ 从响应中解析、$H_m$ 是公开哈希函数、$\beta_t$ 从令牌中解析。客户端不再需要任何秘密密钥来执行验证。

### 问题 2.3（隐私模型 / Simulator 缺失）

**状态：⚠️ 部分解决，建议后续加强**

`commitment.tex:356-363` 的隐私讨论论证了"服务器侧泄露不扩大"，理由是所有新增对象（$\mathsf{rt}$、$\sigma$、$\mathsf{MTree}$、$\mathsf{Open}$）都由服务器已持有的交叉标签集合确定性导出。这个论证在逻辑上是对的——Merkle-open 的所有材料确实是服务器本地可计算的，不像原稿那样引入了新的明文标签回传。

但审稿人的原话是"必须在 IND-CKA2 的 Simulator 中展示如何模拟"。当前的处理方式是用一段定性论证代替形式化 Simulator 构造。对于学位论文，这个深度可以接受，因为论证确实说明了"没有新的服务器侧语义泄露"。但如果后续要投会议，这里需要补一个显式的 Simulator 构造，哪怕只是说明 Simulator 用已有的 $\mathcal{L}_{\mathsf{Search}}$ 就能生成所有新增对象。

## 2. 设计层面的正确性检查

### 绑定链验证

| 绑定环节 | 机制 | 判定 |
|----------|------|------|
| 关键词→根 | 签名覆盖 $I(w_j)\|\mathsf{rt}_{j,u}$，客户端用自己查询中的 $I(w_j)$ 验签，防止跨关键词根替换 | ✅ 正确 |
| 根→叶子 | 叶子哈希包含位置索引 $r$，内部节点用不同前缀，域分离消除编码混淆，位置绑定消除同值叶子互换 | ✅ 正确 |
| 与 Nomos $k$-采样兼容性 | 搜索阶段只恢复 $k$ 个采样地址，附加通信 $O(k \cdot (|\mathbb{G}| + \lambda \log \ell))$，不破坏基础协议令牌语法 | ✅ 正确 |
| $\mathsf{MPos}$ 唯一性 | xtag 碰撞在伪随机群元素模型下概率可忽略，并给出多值映射退化处理 | ✅ 合理 |

### 证明结构验证

命题 5（地址绑定健全性）的 $G_0 \to G_1 \to G_2$ 游戏跳跃：

- $G_1$ 消除根认证伪造 → 归约到 EUF-CMA：归约算法 $\mathcal{B}_1$ 直接输出伪造的消息-签名对，标准且无歧义。
- $G_2$ 消除错误开封 → 归约到 $H_m$ 抗碰撞：沿伪造路径计算得到的根与真实树根相同，导出碰撞，标准且无歧义。
- $G_2$ 中胜利概率为 0：验证算法显式检查 $\mathsf{ProofAddr}_{j,u} \subseteq \mathcal{A}_{j,u}^{\mathsf{open}}$，逻辑闭合。

命题 6（组合可验证性）的并集界：$E_{\mathsf{addr}}$（地址替换）与 $E_{\mathsf{bit}}$（位值伪造）互补，分别归约到本章命题 5 和第二章命题 4，结构清晰。

## 3. 遗留的 Minor Issues

### 3.1 指数写法（原审稿 Minor Issue）

`commitment.tex:51` 仍然写的是 $(\mathsf{xtoken}_{j,u}^{(t)})^{\alpha_u/\rho_j}$。审稿人指出在代数群中直接用标量除法写在指数里不专业。

**建议**：改成 $(\mathsf{xtoken}_{j,u}^{(t)})^{\alpha_u \cdot \rho_j^{-1}}$，并在上下文说明运算在 $\mathbb{Z}_p^*$ 上进行。

### 3.2 定理/命题编号

当前 tex 中"定义 5"是硬编码文本，而 Theorem 和 Proposition 使用 LaTeX 自动编号环境。

**建议**：统一用 LaTeX 自动编号环境（`\begin{definition}...\end{definition}`），避免手动编号与自动编号冲突。

## 4. 总结

改造思路的方向完全正确。从"对称开封 + AE 归约"切换到"Merkle-open + 签名/碰撞归约"，一次性解决了原稿三个结构性缺陷中的两个半：

1. 归约矛盾 → **彻底消除**
2. 协议可执行性 → **彻底修复**
3. 隐私论证 → **逻辑成立，形式化程度可后续加强**

已改写的 `commitment.tex` 在协议描述、证明结构和复杂度分析上都是自洽的。改造的附带收益是搜索阶段附加通信从 $O(\ell \cdot |\mathbb{G}|)$ 降为 $O(k \cdot (|\mathbb{G}| + \lambda \log \ell))$，更符合 Nomos 的 $k$-采样执行语法。
